# HDU-Lolita爱好站 · 期末小结

本文档是对本次前端项目开发的整体回顾与技术小结，从软件工程的角度梳理项目中使用到的各项技术和实践经验。

---

## 一、项目整体架构

### 1.1 技术选型

本项目是一个**纯前端静态网站**，主要使用以下技术：

| 技术 | 用途 |
|------|------|
| HTML5 | 页面结构与语义化标签 |
| CSS3 | 页面样式、布局与动画效果 |
| JavaScript (ES5/ES6) | 页面交互逻辑 |
| Font Awesome | 图标库（通过 CDN 引入） |
| Normalize.css | 浏览器默认样式重置（通过 CDN 引入） |

### 1.2 目录结构

```
dsak/
├── index.html          # 首页
├── README.md           # 站点说明文档
├── css/
│   └── style.css       # 全局样式
├── js/
│   ├── auth.js         # 登录/登出逻辑
│   └── products.js     # 商品数据管理
├── pages/
│   ├── about.html      # 关于 Lolita
│   ├── sales.html      # 贩售信息列表
│   ├── sales-detail.html # 商品详情页
│   └── message.html    # 留言区
├── images/             # 图片资源
└── doc/                # 开发文档
```

**设计思路**：
- 按**功能**划分文件夹：页面放 `pages/`，样式放 `css/`，脚本放 `js/`，文档放 `doc/`。
- 公共资源（样式、脚本）集中管理，各页面通过相对路径引用，避免重复代码。

## 二、代码重用

### 2.1 样式复用

- **全局样式文件**：所有页面共用 `css/style.css`，包含：
  - CSS 变量（`:root` 中定义主题色、文字颜色等）
  - 通用组件样式（按钮、卡片、表格、表单等）
  - 布局工具类（`.container`、`.section` 等）

- **好处**：
  - 修改主题色时只需改一处，全站生效
  - 新增页面时可直接复用现有组件，减少重复编写

### 2.2 脚本复用

- **auth.js**：封装了登录/登出的逻辑，所有页面都引入这个脚本，导航栏右上角的用户状态由它统一管理。
- **products.js**：集中存放商品数据和工具函数（如 `getProductById`、`getStatusLabel`），贩售信息页和详情页共同使用。

### 2.3 外部资源引用（CDN）

本项目没有使用 npm 等包管理工具，而是通过 **CDN 链接** 引入第三方库：

```html
<!-- 样式重置 -->
<link rel="stylesheet" href="https://cdnjs.cloudflare.com/ajax/libs/normalize.css/8.0.1/normalize.min.css">
<!-- 图标库 -->
<link rel="stylesheet" href="https://cdnjs.cloudflare.com/ajax/libs/font-awesome/6.4.0/css/all.min.css">
```

**优点**：
- 无需安装 Node.js 或配置打包工具，降低学习成本
- CDN 有缓存加速，用户加载更快

**缺点**：
- 依赖网络，离线时无法加载
- 版本管理不如 npm 精确

> 对于小型项目或学习项目，CDN 方式足够使用；大型项目建议使用 npm + 打包工具。

## 三、前后端架构说明

### 3.1 本项目的架构

本项目是**纯前端静态站点**，没有后端服务器：

- 所有数据都写在前端 JS 文件中（如 `products.js` 里的商品数组）
- 用户登录只是在浏览器 `localStorage` 中保存昵称，不与服务器通信
- 留言表单提交只是演示效果，不会真正发送数据

### 3.2 如果要接入后端

如果将来需要接入后端（比如真正保存用户留言），架构会变成：

```
┌─────────────┐      HTTP 请求       ┌─────────────┐
│   前端页面   │  ───────────────────▶ │   后端服务   │
│  (HTML/JS)  │  ◀─────────────────── │  (Node/PHP) │
└─────────────┘      JSON 响应       └─────────────┘
                                            │
                                            ▼
                                      ┌───────────┐
                                      │   数据库   │
                                      └───────────┘
```

前端通过 `fetch()` 或 `XMLHttpRequest` 发送请求，后端返回 JSON 格式的数据。这种**前后端分离**的架构是目前主流的开发方式。

## 四、开发与部署工具

### 4.1 开发环境

本项目开发过程中使用的工具：

| 工具 | 用途 |
|------|------|
| VS Code | 代码编辑器 |
| Live Server 插件 | 本地预览，支持自动刷新 |
| 浏览器开发者工具 | 调试 HTML/CSS/JS，查看网络请求 |
| Git | 版本控制 |

### 4.2 本地预览方式

由于是静态网站，有多种方式可以预览：

1. **直接双击 HTML 文件**：可以打开，但部分功能（如 `fetch` 加载文件）可能受限
2. **VS Code Live Server**：右键点击 HTML → "Open with Live Server"，推荐使用
3. **Python 简易服务器**：在项目目录运行 `python -m http.server 8080`，然后访问 `http://localhost:8080`

### 4.3 部署方式

静态网站的部署非常简单：

- **GitHub Pages**：把代码推送到 GitHub，开启 Pages 功能即可免费托管
- **Gitee Pages**：国内访问更快的替代方案
- **传统服务器**：把文件上传到服务器的网站目录（如 Nginx 的 `/var/www/html`）

> 本项目没有使用构建工具（如 Webpack），所以部署时直接上传源文件即可，无需"打包"步骤。

## 五、代码规范性

### 5.1 HTML 规范

- 使用**语义化标签**：`<header>`、`<nav>`、`<main>`、`<section>`、`<footer>` 等
- 所有页面统一使用 UTF-8 编码和移动端适配的 viewport 设置
- 图片添加 `alt` 属性，提升可访问性

### 5.2 CSS 规范

- 使用 **CSS 变量**统一管理颜色，方便全局修改：
  ```css
  :root {
    --pink-600: #d84b8a;
    --text: #5b4b5b;
  }
  ```
- 类名采用**语义化命名**：如 `.btn--primary`、`.status--deposit`
- 避免使用过于复杂的选择器，保持样式可维护

### 5.3 JavaScript 规范

- 使用**自执行函数**避免全局变量污染：
  ```javascript
  (function() {
    // 代码写在这里，不会污染全局
  })();
  ```
- 需要跨文件共享的函数挂载到 `window` 对象上（如 `window.getProductById`）
- 变量和函数使用**驼峰命名法**（如 `getStatusLabel`）

### 5.4 文件组织规范

- 相关文件放在同一目录下
- 文件名使用小写字母和连字符（如 `sales-detail.html`）
- 每个 JS 文件只负责一个功能模块

## 六、项目中的不足与改进方向

### 6.1 当前不足

1. **数据写死在前端**：商品信息直接写在 JS 文件里，修改需要改代码
2. **没有使用模块化打包**：JS 文件之间的依赖关系不够清晰
3. **缺少自动化测试**：功能修改后需要手动测试
4. **响应式适配有限**：部分页面在手机上显示效果一般

### 6.2 改进方向

1. **引入后端或使用 JSON 文件**：把数据和代码分离，方便维护
2. **学习使用构建工具**：如 Vite，可以支持模块化开发和代码压缩
3. **引入 CSS 框架**：如 Tailwind CSS，提高开发效率
4. **完善移动端适配**：使用更多媒体查询，优化小屏幕体验

## 七、总结与收获

通过这个项目，我学习和实践了以下内容：

1. **HTML/CSS/JS 基础**：掌握了网页开发的核心技术
2. **页面布局技巧**：学会使用 Flexbox 和 Grid 进行页面布局
3. **代码组织能力**：理解了如何拆分文件、复用代码
4. **版本控制**：使用 Git 管理代码版本
5. **文档编写**：学会用 Markdown 编写项目文档

虽然这只是一个小型的静态网站项目，但它涵盖了前端开发的基本流程和软件工程的基础实践。这些经验将为后续学习更复杂的框架（如 Vue、React）和全栈开发打下基础。
